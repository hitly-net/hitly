# HITLy weekly changelog — 12 November 2026

**Reporting window:** 7 November (after the previous edition) through 12 November 2026 (Europe/London).

A big week. 57 pull requests merged to HITLy `main` and four to the public HITL spec. Most HITLy changes merged up to 11 November are now running on HITLy Cloud. A handful merged after that (passkeys, branded emails and new app icons among them) are on `main` but not yet deployed; they are marked below. HITLy Cloud remains in closed beta, not generally available.

## An MCP server for agents

Agents can now open approvals and questions in HITLy and read the decision back over MCP, without custom HTTP code. `get_decision` returns the reviewer's typed answer in the same shape as the REST API, runs that have no callback skip the resume step cleanly, and a new guide covers setup. Browser visits to the MCP endpoint now land on the docs instead of an error.

Sources: [HITLy #105](https://github.com/hitly-net/hitly/pull/105), [#129](https://github.com/hitly-net/hitly/pull/129), [#130](https://github.com/hitly-net/hitly/pull/130), [#131](https://github.com/hitly-net/hitly/pull/131), [#132](https://github.com/hitly-net/hitly/pull/132), [#141](https://github.com/hitly-net/hitly/pull/141).

## Typed answers for `ask_user`

When an agent asks a question, the reviewer now gets a proper input for the expected answer type rather than a free-text box, and the decided answer is shown afterwards on web and mobile. The approval API returns the answer schema, so clients know what to render. The spec now makes the typed `answer` field the single, authoritative carrier for an answered question.

Sources: [HITLy #134](https://github.com/hitly-net/hitly/pull/134), [#140](https://github.com/hitly-net/hitly/pull/140), [#145](https://github.com/hitly-net/hitly/pull/145), [HITL spec #15](https://github.com/hitly-net/hitl-spec/pull/15).

## Requests you can verify, created exactly once

Reviewers can view, copy and download the original request an agent submitted, with its content hashes, so what is on screen can be checked against what was stored. Re-sending the same request now safely returns the existing one, a conflicting re-send is refused with a clear `409`, requesters can list and cancel their own requests, and `argsHash` uses a canonical JSON form. The spec now describes this create-once behaviour, the verification guidance and signed callbacks.

Sources: [HITLy #101](https://github.com/hitly-net/hitly/pull/101), [#104](https://github.com/hitly-net/hitly/pull/104), [#108](https://github.com/hitly-net/hitly/pull/108), [#110](https://github.com/hitly-net/hitly/pull/110), [#116](https://github.com/hitly-net/hitly/pull/116), [#117](https://github.com/hitly-net/hitly/pull/117), [HITL spec #13](https://github.com/hitly-net/hitl-spec/pull/13), [#14](https://github.com/hitly-net/hitl-spec/pull/14).

## Safer callbacks

The HTTP plugin now supports authenticated, HMAC-signed callbacks with retries and opt-in lifecycle events, so a requester can trust that a decision really came from HITLy.

Source: [HITLy #106](https://github.com/hitly-net/hitly/pull/106).

## Account security

Signed-in users can change their password (other sessions are signed out) and change their email address, which only switches after the new address is confirmed. Multi-factor sign-in with an authenticator app and recovery codes is live. Passkeys are merged but **not yet deployed**. An SSO design note for Google, GitHub and Microsoft sign-in has been published; SSO itself is not built yet.

Sources: [HITLy #114](https://github.com/hitly-net/hitly/pull/114), [#121](https://github.com/hitly-net/hitly/pull/121), [#122](https://github.com/hitly-net/hitly/pull/122), [#124](https://github.com/hitly-net/hitly/pull/124), [#126](https://github.com/hitly-net/hitly/pull/126), [#127](https://github.com/hitly-net/hitly/pull/127), [#128](https://github.com/hitly-net/hitly/pull/128), [#154](https://github.com/hitly-net/hitly/pull/154) (not yet deployed), [#157](https://github.com/hitly-net/hitly/pull/157), [#150](https://github.com/hitly-net/hitly/pull/150) (design note).

## Projects and the inbox

Projects can now be live, paused or archived: pausing stops new items while reviewers can still finish open ones. A project can no longer lose its last admin. Pending lists and counts show only items still waiting for a human, expired questions drop out correctly, and paging no longer hides items past the first page. Workspace invite links were also fixed.

Sources: [HITLy #142](https://github.com/hitly-net/hitly/pull/142), [#152](https://github.com/hitly-net/hitly/pull/152), [#137](https://github.com/hitly-net/hitly/pull/137), [#135](https://github.com/hitly-net/hitly/pull/135), [#136](https://github.com/hitly-net/hitly/pull/136), [#123](https://github.com/hitly-net/hitly/pull/123), [#125](https://github.com/hitly-net/hitly/pull/125), [#138](https://github.com/hitly-net/hitly/pull/138), [#103](https://github.com/hitly-net/hitly/pull/103).

## Mobile

The server side of Android push notifications is merged and deployed; delivery to phones arrives with a future app release. The Android release build was fixed, the inbox gained a refresh, and new HITLy app icons and splash screen are merged but **not yet released**.

Sources: [HITLy #143](https://github.com/hitly-net/hitly/pull/143), [#102](https://github.com/hitly-net/hitly/pull/102), [#109](https://github.com/hitly-net/hitly/pull/109), [#153](https://github.com/hitly-net/hitly/pull/153) (not yet released).

## Privacy and polish

Approval detail views and the inbox now keep sensitive values out of what is sent to the browser and mobile app. Self-hosted installs collect no telemetry by default. Branded notification emails are merged but **not yet deployed**, and user-facing copy now uses consistent HITLy branding.

Sources: [HITLy #113](https://github.com/hitly-net/hitly/pull/113), [#115](https://github.com/hitly-net/hitly/pull/115), [#118](https://github.com/hitly-net/hitly/pull/118), [#156](https://github.com/hitly-net/hitly/pull/156), [#149](https://github.com/hitly-net/hitly/pull/149) (not yet deployed), [#144](https://github.com/hitly-net/hitly/pull/144).

## Docs for people and agents

The website now publishes `robots.txt`, a sitemap, `agents.md` and `llms.txt`-style files so agents can read HITLy's docs directly. An architecture overview was added.

Sources: [HITLy #133](https://github.com/hitly-net/hitly/pull/133), [#146](https://github.com/hitly-net/hitly/pull/146), [#155](https://github.com/hitly-net/hitly/pull/155), [#148](https://github.com/hitly-net/hitly/pull/148).

## HITL spec

Besides the changes above, the spec adds a non-normative citation of independent crash-and-resume research next to the replay-after-restart conformance check.

Source: [HITL spec #12](https://github.com/hitly-net/hitl-spec/pull/12).
