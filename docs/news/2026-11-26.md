# HITLy weekly changelog — 26 November 2026

**Reporting window:** 19 November (after the previous edition) through 26 November 2026 (Europe/London).

The headline: plan limits are now enforced on every capped action, and HITLy is officially a registered UK trade mark. Seven pull requests merged to HITLy `main` this week, covering plan enforcement, the legal notice, a new blog section, and fixes and build tooling for the mobile app. Not everything merged this week is live yet; each section says whether it is deployed. There were no merged changes to the public HITL spec this week.

## Plan limits enforced everywhere

Every action that a plan caps now checks the limit on the server before it writes anything: creating projects or restoring them to live, adding members and sending invites, creating API keys, taking in new decision requests each month, and resuming old completed items. When a limit is reached, the request is refused with one consistent `tier_limit_reached` error (HTTP 402 on the REST API), and nothing is half-written. Limits always come from the workspace's plan on the server, never from anything the client sends.

Two details matter for integrators. Replaying an idempotent request never uses up quota, and two requests racing for the last free slot can no longer both get through. Rotating an API key does not count as a new key, and deleting one frees its slot. Self-hosted installs are not capped.

Status: merged on 25 November; not yet deployed to HITLy Cloud as of 26 November.

Sources: [HITLy #195](https://github.com/hitly-net/hitly/pull/195).

## HITLy® is a registered UK trade mark

The UK word mark for HITLy is now registered, and the legal notice on hitly.net says so: "HITLy® is a registered trade mark of Metaspan Ltd in the United Kingdom (UK00004435292)." The ® appears only in that sentence, and tests pin the wording.

Status: deployed; the updated legal notice is live on hitly.net.

Sources: [HITLy #178](https://github.com/hitly-net/hitly/pull/178), [#180](https://github.com/hitly-net/hitly/pull/180).

## A blog on hitly.net

The marketing site gains a `/blog` section with two launch posts on human oversight of AI agents in regulated finance: one on the FCA's agentic AI expectations for firms and technology providers, and one on the EU AI Act's human oversight and record-keeping duties for AI in financial services. Both map those duties to what HITLy records (who reviewed what, when, and with what outcome) and carry a clear disclaimer that HITLy is a technology provider, not a law firm, and makes no compliance claims.

Status: merged on 26 November; not yet published on hitly.net.

Sources: [HITLy #204](https://github.com/hitly-net/hitly/pull/204).

## Mobile app fixes

- **Expired sessions go back to sign-in.** When a session expired on the server, the Android app used to sit on an "Unauthorized" error. It now clears the stale session and returns you to sign-in. A wrong password at sign-in never signs you out of an existing session.
- **Current brand mark in the menu.** The navigation drawer showed an old text logo that was clipped; it now shows the HITLy app icon and wordmark.
- **Launcher icon check.** The Android release build now fails if the built app is missing its launcher icon, so a build can no longer ship with a blank icon.

Status: merged on 26 November; these reach devices with the next app build.

Sources: [HITLy #206](https://github.com/hitly-net/hitly/pull/206).

## Repeatable iOS builds

The mobile app now has an in-repo, repeatable way to build for iOS, matching the existing Android flow. Simulator and unsigned builds need no Apple credentials at all; signed device and TestFlight builds fail fast with a clear message when credentials are missing, without prompting or printing secrets. A follow-up made the local simulator build more robust: it checks the CocoaPods version, installs pods after prebuild, and checks that the requested simulator exists before building.

Status: build scripts and docs only; nothing to deploy.

Sources: [HITLy #193](https://github.com/hitly-net/hitly/pull/193), [#203](https://github.com/hitly-net/hitly/pull/203).
