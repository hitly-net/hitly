# HITLy weekly changelog — 7 November 2026

**Reporting window:** 31 October through 7 November 2026 (Europe/London).

Three pull requests merged to `main` this week across HITLy and the public HITL spec. These are merged changes, not a deployment announcement. HITLy Cloud remains in closed beta, not generally available.

## Clearer approval evidence

HITLy now records when an eligible reviewer first opens an approval and adds information about who decided and the client they used. This makes approval histories easier to understand. Opening an approval does not mean it was read, and IP addresses are not recorded. Existing evidence remains compatible.

Source: [HITLy #97](https://github.com/hitly-net/hitly/pull/97).

## Clearer single-use response rules

The public spec strengthens its single-use response requirements, clarifies retention expectations and explains that completed requests remain terminal. These rules help implementers build more predictable approval workflows.

Source: [HITL spec #10](https://github.com/hitly-net/hitl-spec/pull/10).

## A reusable conformance example

A new standalone example helps implementers check their requester against the spec across process restarts. The contribution reports validation on Windows with Node 24; it is not yet part of the repository’s validation script or CI. This is an implementation aid, not a claim that every integration has passed.

Source: [HITL spec #11](https://github.com/hitly-net/hitl-spec/pull/11).
