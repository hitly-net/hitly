Here's the full landscape review. Key takeaways for your abstraction goal:
Two separate problems, two separate layers. The pause primitive (Mastra's suspend()/resume(), LangGraph's interrupt(), Temporal's signals) is fundamentally framework-specific, but the reviewer-facing UI doesn't have to be — that's the layer worth abstracting.
AG-UI is the strongest candidate for your framework-agnostic UI layer — it's already got native adapters for Mastra, LangGraph, CrewAI, Pydantic AI, Agno, and LlamaIndex, and CopilotKit (MIT, 20k+ stars) is the reference React implementation built directly on it. Building your approval UI against AG-UI's event stream means you don't rewrite it when you add framework #2.
LangChain's Agent Inbox schema (HumanInterrupt — action + editable args + allowed-actions config + markdown context) is a genuinely good candidate for your canonical internal approval envelope, even though the UI itself is LangGraph-specific.
HumanLayer and gotoHuman both operate at the tool-call layer rather than the orchestration layer, which is exactly the kind of framework-agnostic positioning you want — HumanLayer via a @require_approval decorator pattern, gotoHuman via an open-source MCP server.
For mobile, ntfy.sh (self-hostable, Apache/GPL) is the standout — there's already a working reference implementation (claude-push) wiring Claude Code's permission hooks to ntfy push notifications with tap-to-approve/deny, which is essentially the exact pattern you'd want for Tourbillon's harness workflows.
The report's final section proposes a concrete layered architecture — canonical envelope → per-framework pause adapters → AG-UI reviewer UI → ntfy mobile layer — so adding a new framework later only means writing one adapter, not touching the UI or mobile layer.

Yes — RunMyJobs by Redwood is Redwood's offering here, but it's a commercial, closed-source SaaS platform, not an open-source tool like the ones from the earlier research (AG-UI, HumanLayer, gotoHuman, Agent Inbox, ntfy.sh).
Key points on fit:
What it is: RunMyJobs is a full-stack workload automation (WLA) and orchestration platform, and it's the only WLA solution certified as an SAP Endorsed App (Premium) and included in the RISE with SAP reference architecture. It supports bidirectional integration with SAP — SAP systems can trigger and control RunMyJobs workflows and vice versa.
Approval capability: It explicitly supports workflow approvals as part of end-to-end process orchestration (e.g. financial close, procure-to-pay, meter-to-cash), with business rules, SLA management, and "intelligent reactions" defining escalation logic without custom code.
AI/agentic angle: Redwood has recently positioned RunMyJobs as an "agentic orchestration platform," with GenAI steps nestable into automations and bidirectional integration with SAP Joule (SAP's AI assistant), so approvals can be surfaced directly inside Joule.
Licensing: This is a proprietary SaaS product (on-prem/cloud/SaaS deployment options), sold via SAP Store — not open source. There's no publicly available SDK or approval-UI component library comparable to CopilotKit or Agent Inbox.
Bottom line: If your Tourbillon-style abstraction needs to interoperate with SAP landscapes specifically, RunMyJobs is the enterprise-grade, SAP-certified equivalent — but it's a commercial black box rather than something you'd fork or embed. For your open-source, framework-pluggable HITL layer, it would sit as an external system you integrate with via webhook/API (similar to how you'd treat Slack or gotoHuman), not as a component you build on top of.
